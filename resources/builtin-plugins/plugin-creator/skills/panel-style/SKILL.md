# 面板风格：造一个，不是选一个

> 改编自 impeccable（Apache-2.0）、花叔 Design（MIT）、Anthropic frontend-design（Apache-2.0），署名见插件根目录 NOTICE。

## 为什么要费这个事

你有自己的默认审美。没有约束时，你会落到下面几处之一。它们不丑，但与内容无关地出现，读起来就是“AI 做的”或“像某一家”：

- **Kimi 式**：天蓝色块与渐变、字符 / ASCII 纹理、超大号数字、近黑卡。
- **分诊式**：圆角卡片竖排、判定徽章 + 三格信号条、汇总卡大数字 + 分布条。
- **暖奶油式**：暖奶油底、高反差衬线标题、陶土色点缀。
- **SaaS 卡片套件**：一样的圆角、一样的浅阴影、每块内容一张卡、`01 / 02 / 03` 编号、全大写小标签、`A · B · C` 中点串。
- **深底单点缀**：近黑底 + 一个荧光色。
- **粗野主义套件**：平涂饱和色块 + 黑粗描边 + 硬偏移投影 + 粗压缩展示字。
- **细线报纸**：发丝线、零圆角、密排分栏、斜体衬线标题、小号等宽标签。

这些**不是禁用项，是“已经花掉的第一反应”**：三个方向里最多一个落在其中，而且必须是故意的、写明理由。**账本里最近 3 次用过的样子，这次也算花掉了。**（只靠禁用清单反而有害：禁掉一个默认，你会滑到下一个。所以下面用“从内容里长出来 + 骰子”，不用“别做 X”。）

## 面板是什么样的约束（先记住）

- 一份**自包含的 HTML**：内联 `<style>` / `<script>`，图片字体只能 `data:`，**不能联网、不能引外部文件、不能用 `eval` / `new Function`**。在沙盒 iframe 里，不能跳转链接。
- 宿主给的宽度大约 **360–440px**（右栏），高度给满，模板自己滚动。浅色 / 暗色主题都要成立（宿主下发主题变量，见 `assets/panel-template.html`）。
- 数据来自 `orbita.panel.data` 指向的 JSON（第 4 步已经跑出真数据）；动作按钮发 `orbita:action`。

### 写模板的八条规则（面板那头实测出来的）

`assets/panel-template.html` 已经全部做到，**以它为底改渲染部分，别动收发那套**：

1. **自包含**：样式与脚本都内联；图片 / 字体只能是 `data:`；不能联网、不能引外部文件、不能 `eval` / `new Function`。
2. **透明底 + color-scheme**：`<meta name="color-scheme" content="light dark">` 加 `html, body { background: transparent }`。宿主给满面板、露出面板自己的底色；不写的话深色主题下会被浏览器刷成不透明白底。
3. **收数据**：`window.addEventListener("message", e => { if (e.source !== parent) return; … })`，只信宿主。`m.data` 是数据文件内容（空态时 `null`，`m.state === "empty"`），`m.theme.vars` 用 `document.documentElement.style.setProperty` 套到 `:root`，`m.theme.scheme` 是 `"light"` / `"dark"`。每次数据文件变化或主题切换都会再来一条，**渲染要能重复做**（先清空再画，不要追加）。
4. **样式用宿主变量并带回退**：`var(--color-text-primary, #202124)`、`var(--font-size-sm, 12px)`。名单：`--color-text-primary/secondary/tertiary`、`--color-bg-panel/-muted`、`--color-chat-card-bg`、`--color-border-subtle/default/strong`、`--color-accent/-soft/-fg`、`--color-success/warning/danger/info`、`--font-family-base/mono`、`--font-size-xl/lg/base/sm/xs`、`--radius-sm/md/lg/xl`、`--line-height-ui/tight`。拿不到 Orbita 打包的字体，用系统字体栈兜底。
5. **空态**：自己画了空态就发 `parent.postMessage({ type: "orbita:ready", emptyState: true }, "*")`；不发也行，但数据为空时宿主会盖一行「还没有产出」。
6. **动作回传**：`parent.postMessage({ type: "orbita:action", action: "feedback", payload: {…} }, "*")`。动作名 ≤ 64 字符，载荷序列化后 ≤ 16 KB，每 10 秒 ≤ 20 条。宿主只把它追加成一行 `{"at","action","payload"}` 到 `<插件数据目录>/actions.jsonl`，**不会替你做任何别的事**；你的脚本下一轮去读它，用 `at` 判断哪些是新的。
7. **数据文件原子写**：脚本先写临时文件再改名。写到一半被读到，面板只会多一条“读不出来”的说明、保留上一份。
8. **数据 ≤ 2 MB**：超了面板拒读。别把全量历史塞进去，面板只放当前要看的。
- 这是 Read / Operate 界面，不是海报：表现力的雄心体现在**精确与克制**。每张卡至多三档字号，展示字体只给签名元素；正文对比度 ≥ 4.5:1；正文不小于 `--font-size-sm`。

## 步骤

### 1. 读三样东西

- 工作区的 `plugins/.style-ledger.json`（账本，没有就当空）：最近 5 次交付的风格名、骨架、主色色相、签名元素。
- 这个插件的 `intent.md`（意图、验收清单、品味参照）和已有的 `taste.md`（用户原话）。
- **真数据**：`data/panel.json` 里至少 3 条。没有真数据不开工——回第 4 步。

### 2. 把用户的话翻成风格简报（不写长什么样）

```yaml
brief:
  面板: 文献追踪
  用户原话: "……"            # 逐字，不改写
  用户要做的动作: 扫一眼决定读不读，标记有用 / 不相关
  场景: 右栏 400px；一天看一次；浅色和暗色都要成立
  每条必须一眼读到的: [它解决的具体问题, 相关度]
  可以藏起来的: [作者, 来源路径]
  不要: 用户明确否定过的东西
```

用户描述里的风格词（“像报纸”）只收窄解释空间，**不替他选**：三个方向都在“报纸”语境里，各出一种诠释。

### 3. 从内容的世界里列七个候选（脑内完成，不展示）

问自己：这个内容在网页出现之前是什么样的东西？它的读者每天熟读的印刷物、标记系统、仪式是什么？它作为实物会是什么？论文：抽印本封套、图书馆借书卡、期刊目录页、审稿意见单、会议胸牌、索引卡片柜、书脊。待办：便利贴墙、值班表。天气：航海日志、农历。**每个候选写两行**：为什么能承载“用户要做的动作”；它的底色、主色、字体声音，以及一个让它被认出来的签名。

两条约束：七个里超过三个属于同一种材料（全是纸、全是屏幕）= 你停在了最显眼的物件上，继续挖；Operate / Read 界面**不许扮成工具本身**（终端、仪表盘、控制台）。

### 4. 选方向：骰子，不按你的排序

先跑 `date +%S` 取当前秒数 S（Windows 用 `powershell -c "(Get-Date).Second"`）。

| 槽位 | 怎么挑 |
|---|---|
| 方向 1 | 七候选里的第 `S % 7 + 1` 号。**不许换成你更喜欢的** |
| 方向 2 | 剩下六个里**骨架和方向 1 最不一样**的 |
| 方向 3 | 你自己想不到的那一个：回头看 S，取候选 `(S × 3) % 7 + 1`，若与前两个撞了顺延；它落在上面“已花掉”清单里也可以留，但必须和内容融合（只借形式，颜色与签名从内容来），并在方向卡上标“默认簇，已融合” |
| 出口 | 一张**设计系统原生**的正经面板：只用宿主主题变量、列表行、小标签，不加任何风格。它是用户的门，**不推荐它、不拿它和前三个比**；只出 1 个，不单独让他选 |

三个方向必须**骨架不同**，不能只是配色不同：信息的排列方式、哪个元素最大、条目之间的关系（堆叠 / 列表行 / 表格 / 时间线 / 单张大卡加托盘）至少两项不同。

### 5. 每个方向写一张方向卡（给用户看，六栏）

| 栏 | 写什么 |
|---|---|
| 名字 | 1–3 个字的中文名 + 英文名，以后复用的把手（例“审读单 Referee form”） |
| 来源 | 七候选第几号 / 骰子 |
| 借的是什么 | 具体规则：网格、字号比、主色占比。不写情绪词 |
| 骨架 | 一句话 |
| 签名元素 | **唯一**一处最大胆的地方，其余都服务内容 |
| 只有这个内容才有 | 一句话：这个设计里哪个东西是这类内容独有的 |

**颜色按内容推导，不抄配方**：从内容自带的色彩记忆采样，压到 2–3 个有彩色 + 一组中性明度，再写一句“为什么是这个色”。写不出这句话，就是在抄配方。

### 6. 自审（写代码前，逐张问）

1. **同类测试**：换一种内容（论文换成新闻），我会不会做出几乎一样的东西？会，就是没从内容里长出来。
2. **去掉测试**：把签名元素去掉，信息是更清楚还是更糊？更清楚，说明它用力过头了。
3. **认得出测试**：把文字全抹掉，还认得出是哪个方向吗？
4. **默认测试**：它落在“已花掉”清单里了吗？
5. **三张互比**：是不是挤在同一个温度、同一种材料里？

### 7. 做真小样，放进右栏让用户点着比

插件这时已经装上（plugin-creator 第 5 步），右栏就是它的面板，**你改 `panel/index.html`，右栏几秒内就变**。所以不做单独的对比页，直接把几个方向放进面板里：

1. 每个方向先各写一份草稿，放 `panel/drafts/`（`a-<名>.html`、`b-<名>.html`、`c-<名>.html`、`exit.html`），**以 `assets/panel-template.html` 为底**（它处理好了：接收 `orbita:data`、设主题变量、空态、动作回传），只改渲染部分和样式。
2. 把它们**合成一个**自包含的 `panel/index.html`（面板不能引外部文件，只能内联）：
   - 顶上一排切换键（方向名，如「审读单 · 书堆 · 荧光笔 · 原生」），默认选第一个；
   - 每个方向的样式用各自的根类名隔开（`.dir-a …`、`.dir-b …`），渲染函数各写一个，切换时只换根类名并重画；
   - 收数据、主题、空态、动作回传只写一份，四个方向共用；
   - 切换键本身用宿主下发的变量（`--color-*`、`--font-size-sm`），做得朴素，别抢方向本身的戏。
3. 告诉用户：“右栏现在有 4 个方向，点顶上的名字切换；方向卡在下面。”再把每个方向的**方向卡**发在对话里。
4. 有浏览器工具、模型也能看图的话，可以另外截一两张给他做对照，但**主路径是右栏**；看不了图就明说，不要声称“渲染正常”。
5. 右栏里看不到（比如他没在看这条对话）：让他点右侧图标条上插件名首字的页签。

**摆出来就停**，等他挑。不替他选，不在没看到小样前问“你想要哪个方向”。

**诚实汇报你验证过什么。** 方向卡里只写你真验证过的（文字出来了没有、点击有没有反应），版式好不好、有没有挤成竖排、有没有溢出，由用户在右栏里看了判断。

### 8. 他挑中之后

- 把挑中的那个方向写成**只有它**的 `panel/index.html`（去掉切换键和其它方向），右栏几秒内变成定稿；删掉 `panel/drafts/`（留着会被当成插件内容）。
- 写 `plugins/<名字>/taste.md`：

  ```markdown
  # 品味记录
  ## 2026-11-05 · 文献追踪面板
  - 选了：审读单 Referee form（骨架：一整张连续表格……）
  - 否决：书堆 Library stack —— 用户原话：“……”
  - 否决：荧光笔 Highlighter —— 用户原话：“……”
  - 他当时说的其它话（逐字）：“……”
  - 适用范围：只用于这个插件的面板；扩到别的卡要他点头
  ```
- 往工作区 `plugins/.style-ledger.json` 追加一条 `{ "id", "name", "skeleton", "hue", "signature", "date" }`（没有文件就新建，数组，最多留 20 条）。
- 对用户说一句：“这句我记进插件里的 taste.md 了。”

### 9. 以后再改这个面板

先读 `taste.md` 和 `panel/index.html`，照它的方向改，不重新激发。用户说“换一个”才回第 3 步（账本会让你避开刚用过的）。用户只想微调（密度、圆角、字重反差）：旋 3–5 个旋钮，把非默认值写回 `taste.md`。

## 防止落回千篇一律

- 骰子决定哪两个候选进入展示，你的排序不算数。
- “加选项，不加禁令”：外观家族（暖纸衬线、深底单点缀……）本身不是问题，**三个方向挤在同一个家族**才是。
- 不直接套某家品牌的设计系统；现实参照只借规则（栅格、字号比、主色占比），不借外观。
- 整张卡做成道具、套万能隐喻，三张里最多一张，并且要过“去掉测试”。
- 在“默认簇”里留一个方向时，诚实地写“默认簇，已融合”，别包装成原创。
