# 做插件：和用户一起从头做到装好

> 你不是在“生成一个插件”，你是在和用户一起把他反复做的一件事，做成一个能装进 Orbita、能看到工作流、能看到产出的东西。
> 用户最在意的是：**过程里能看见、能挑、能说“不是这样”**，而不是你一口气交出一个成品。

## 先认路

这个技能所在的文件夹 = 本 SKILL.md 所在的目录（下文记作 `<本技能>`）。里面有：

| 位置 | 什么时候读 |
|---|---|
| `<本技能>/references/plugin-layout.md` | 搭骨架、写 plugin.json、workflow、userConfig、MCP、脚本约定、常见坑——**第 3 步前必读** |
| `<本技能>/references/skill-writing.md` | 写插件里的技能（SKILL.md）之前读，几分钟 |
| `<本技能>/assets/plugin-skeleton/` | 骨架模板（plugin.json、一条示例技能、示例脚本、taste.md），第 3 步整份拷过去再改 |
| `../find-existing/SKILL.md` | 第 2 步“主动找现成的”：按它做 |
| `../panel-style/SKILL.md` | 第 6 步“出面板方向”：按它做（含面板模板与右栏里的对比版） |

工具：`list_plugins`（先看已有的）、`install_plugin`（第 5 步就装，见下）、`create_skill`（**不用它**：插件里的技能直接写在插件文件夹里）、浏览器工具（给用户看面板方向的截图）。

## 流程（七步，按顺序；每步结束用一两句话告诉用户你做了什么）

**什么时候停下来等用户：** 第 1 步的意图确认（可以一口气带过）、第 2 步选候选、第 5 步点确认卡、第 6 步挑面板。其余自己往下做，别每步都问。

**为什么第 5 步就装：** 用户要**一边聊、一边在右栏看面板变化**。装上以后右栏会自动切到这个插件的面板；它是链接安装，你之后改 `panel/index.html` 或数据文件，右栏几秒内跟着变，不用再装。所以先装一个能看的版本，再在右栏里和他磨面板，而不是最后才装。

### 1. 听需求，写下意图与验收清单

最多问 3 个问题，先看用户已经说了什么再问，别问他刚说过的：它每次要产出什么（用户最后看什么）？多久跑一次、数据从哪来？有没有他见过、喜欢或讨厌的样子（品味参照）？

然后在工作区建 `plugins/<名字>/intent.md`（名字规则见 layout 参考），**三层**：

```markdown
# 意图
一句话：给谁、做什么、产出什么。

# 验收清单
- [ ] 每条都能检查，写成“看到 X 就算对”。例：跑一次能产出 ≥5 条带一句话摘要的论文；摘要里没有原文标题的复述。

# 品味参照
- 用户的原话（逐字）：“……”
- 他给过的链接 / 截图 / 点名的产品：……
```

把这三层贴给用户看（短），他不吭声就当通过；他改了就改文件。**验收清单是后面第 4、5 步自检的依据，不是摆设。**

### 2. 主动找现成的

不要等用户说“有没有现成的”。动手写之前，按 `../find-existing/SKILL.md` 找一遍，给 **2–3 个候选**并说明各自能复用什么、要改哪里、许可证是什么。先调用 `list_plugins` 看这个工作区里是不是已经有类似的插件（有就问他是改它还是另做）。找不到合适的就直说“没找到，我从头写”，别硬凑。

### 3. 搭骨架

读 `references/plugin-layout.md`，然后：

```bash
mkdir -p "<工作区根>/plugins/<名字>"
cp -R "<本技能>/assets/plugin-skeleton/." "<工作区根>/plugins/<名字>/"
```

（第 1 步写下的 `intent.md` 已经在这个文件夹里，骨架不带它，不会被覆盖。）

骨架里 `__NAME__`、`__SKILL__` 这类占位要全部换掉（目录名也是：`skills/__SKILL__` 改成真技能名）。**只能写在 `<工作区根>/plugins/<名字>/` 里面**——`install_plugin` 只认工作区内的路径。`.claude-plugin/plugin.json` 里要有 `orbita.workflow`（给人看的步骤列表，每步最好点名本插件里的一条技能）。

### 4. 写技能和脚本，真跑一次

按 `references/skill-writing.md` 写每条技能（SKILL.md 的 description 要具体、“推”一点），脚本放 `scripts/`。然后**真的跑一次**，产出**真实数据**写到 `orbita.panel.data` 指向的文件（骨架默认 `${CLAUDE_PLUGIN_ROOT}/data/panel.json`，也就是 `plugins/<名字>/data/panel.json`）。

- 数据必须是真的。网络不通、接口变了就如实告诉用户，不要编造样例当成产出；实在要用样例预览面板，必须在 `panel.json` 里标 `"sample": true`，并告诉用户。
- 拿 `intent.md` 的验收清单逐条对产出，没过就改脚本再跑，不要带着没过的清单进下一步。
- 给用户看 2–3 条真实记录（不是整个文件）。

### 5. 先装上，让面板出现在右栏

第 4 步跑出真数据后马上装，不等面板定稿：

1. 如果还没有 `panel/index.html`：把 panel-style 技能自带的面板底稿（它目录下 assets 里的 `panel-template.html`）拷过去当**占位面板**（它会把 `data/panel.json` 里的条目列成朴素的卡片），先让用户看到数据。
2. 自检：`plugin.json` 是合法 JSON；`orbita.workflow` 里每个 `skill` 都是本插件里真有的技能；每条技能有 description；`orbita.panel.template` 文件存在。
3. 调用：

```
install_plugin({ path: "<工作区根>/plugins/<名字>" })
```

它会在对话里弹一张确认卡，**用户点“安装”才装**。调用后别重复调、别催；被拒绝就问他想改什么，别自己重试。返回错误（清单不对、重名、路径越界）时，错误里写了怎么改，改完再调。

装好后右栏会**自动切到这个插件的面板**（用户正看着这条对话时）。告诉他一句：“右栏现在是它的面板，接下来我们直接在那儿磨样子；我改文件，它几秒内就会变。”如果右栏没自己打开，让他点右侧图标条上那个**插件名首字**的页签。

用户不想要面板：把 plugin.json 里的 `orbita.panel` 整块删掉再装（否则会报模板找不到），并跳过第 6 步。

### 6. 面板：在右栏里出 2–3 个骨架不同的方向，让用户挑

按 `../panel-style/SKILL.md`。要点：方向之间**骨架不同**（不是换色），用第 4 步的真数据渲染；**把几个方向放进同一个 `panel/index.html`，顶上一排切换键**，用户直接在右栏里点着比（做法见 panel-style 第 7 步）。**摆出来就停，等他挑**，不替他选。他挑中后：

- `panel/index.html` 只留挑中的那一个（去掉切换键和其它方向），右栏几秒内就变成定稿；
- 把他的取舍写进 `plugins/<名字>/taste.md`：选了哪个、否决了哪些、他的**原话**（逐字）、日期；
- 然后明说一句“这句我记进插件里的 taste.md 了”。

之后他再说“这里改一下”，直接改 `panel/index.html`，让他看右栏，不用重装。

收尾告诉用户去哪看：插件页 → 点这个插件 → “工作流”一块是你写的步骤（点技能名可只读查看它的 SKILL.md），“面板”“最近产出”能看到数据文件和他点过的反馈。**技能要到下一轮才加载**，所以让他新开一条对话再试，或你直接按它的 SKILL.md 做一次演示。

### 7. 问要不要定时跑

最后问一句：“要不要让它每天（或每周）自己跑一次？”**只是提议**：自动化里“选插件”这块还没做，你不会、也不该替他建；把入口技能名和建议的时间告诉他，说清楚现在要定时只能自己在自动化里建一条指向这个技能的任务。

## 做对的标准

- 用户在任何一步说“不是这样”，改，别辩解；他的原话写进 `taste.md` 或 `intent.md`。
- 每次给用户看东西，都是**真数据**、**真截图**、**真路径**。
- 回复用他的语言，大白话，不堆术语（“工作流”“技能”可以说，“manifest”“frontmatter”别说）。
- 不在用户的机器上装全局依赖（`pip install`、`npm i -g`），脚本只用标准库；真需要第三方库先问。
- 密钥、令牌不写进任何文件；需要时用 plugin.json 的 `userConfig`（`sensitive: true`），脚本从环境变量读。
- 做完在对话里给一张**小结**：插件名、放在哪、技能列表、一句话怎么用、没验证的是什么（诚实写）。

## 常见走偏（遇到先对照这里）

| 现象 | 原因 | 做法 |
|---|---|---|
| `install_plugin` 报“outside this session's workspace” | 插件不在工作区里 | 搬到 `<工作区根>/plugins/<名字>/` |
| 报 workflow 点名了不存在的技能 | `skill` 写的既不是技能目录名也不是 SKILL.md 里的 name | 改成本插件里真有的 |
| 装好了但新对话里看不到技能 | 技能下一轮才加载；或 SKILL.md 缺 description | 看返回信息；补 description |
| 面板一直是空态 | `panel.json` 路径对不上，或脚本写到了别处 | `orbita.panel.data` 里的路径就是脚本该写的路径 |
| 面板里点链接没反应 | 面板在沙盒里，不能跳转、不能联网 | 链接当文字显示，或发一个 `orbita:action` |
| 与用户已有技能重名 | 技能目录名撞了 | 改插件里的技能名（目录名和 SKILL.md 的 name 一起改） |
