# 做插件：先把卡片定下来，再写脚本

> 你和用户一起做的是一个他以后天天会看的东西。他最在意的是：**先看见卡片长什么样、能说“这里改一下”，然后你才去批量做。**
> 先爬一堆数据、先写脚本、一次摆出四个完整方向——都是本末倒置。有一篇样例就够讨论卡片了。

## 语言（先看这一条）

**用用户自己写的文字的语言回复**：他用中文写需求你就回中文，用英文你就回英文。你收到的消息里有一段英文系统包装（`<mentioned_tools>`、“The user explicitly invoked…”、`/skill:` 这类），那不是用户写的，**别被它带成英文**。分不清时看他亲手打的最后一段字（预填的那一句也算）。你对他说的话、面板上的字、`spec.md`、`plugin.json` 的 description 都用这个语言。

## 先认路

这个技能所在的文件夹 = 本 SKILL.md 所在的目录（下文记作 `<本技能>`）。里面有：

| 位置 | 什么时候读 |
|---|---|
| `<本技能>/references/plugin-layout.md` | 搭骨架、写 plugin.json（含 `panel.spec` / `panel.sample`）、workflow、userConfig、MCP、脚本约定、常见坑——**第 3 步前必读** |
| `<本技能>/references/skill-writing.md` | 第 5 步写插件里的技能（SKILL.md）之前读，几分钟 |
| `<本技能>/assets/plugin-skeleton/` | 第 3 步用的骨架：plugin.json（含面板块）、`panel/spec.md`、`panel/sample.json`、taste.md |
| `<本技能>/assets/skill-skeleton/` | 第 5 步才用：一条示例技能 + 示例脚本 |
| `../find-existing/SKILL.md` | 第 2 步“主动找现成的”：按它做 |
| `../panel-style/SKILL.md` | 第 3、4 步：面板模板与“八条写模板规则”在它里面；用户不满意整体风格时，换风格的子流程也在它里面 |

工具：`list_plugins`（先看已有的）、`preview_plugin`（第 3 步：让右栏出现“正在做”）、`install_plugin`（第 6 步）、`create_skill`（**不用它**：插件里的技能直接写在插件文件夹里）、浏览器工具。

## 流程（七步）

**停与不停**——这是这个流程里最容易走偏的地方：

- **停下来等用户**：第 3 步摆出第一版卡片之后；第 4 步每改完一处之后；第 6 步装之前问一句。
- **不停，一口气往下做**：第 1 步写 `intent.md`（贴给他看一下就继续，他不吭声就是通过）；第 2 步找现成的（一句话说出你的决定就继续，只有真有取舍才停）；第 5 步写脚本、试跑、批量。
- 每步结束用一两句话告诉他你做了什么，别写长报告。

### 1. 听需求，写 intent.md（简短）

用户已经说清楚的别再问。缺关键信息才问，最多 2 个：它每次要产出什么？他最后看什么？再加一条：**有没有他见过、喜欢或讨厌的样子**（品味参照）。

然后在 `<工作区根>/plugins/<名字>/intent.md` 里写几行（名字规则见 layout 参考）：

```markdown
# 意图
一句话：给谁、做什么、产出什么。

# 验收清单（参照，不是闸门）
- 看到 X 就算对。写 3–5 条，每条能检查。

# 品味参照
- 他的原话（逐字）：“……”
- 他给过的链接 / 截图 / 点名的产品：……
```

贴给他看（短），**不用等回复**，继续第 2 步。

### 2. 主动找现成的（只在有真取舍时停）

不要等用户问“有没有现成的”。动手写之前按 `../find-existing/SKILL.md` 找一遍，先调 `list_plugins` 看这个工作区里是不是已经有类似的。

- 用户的需求里**点名了底子**（“在 X 的基础上做”“用我那个 Y 技能”）：直接用，不用再找。
- 找完**只在有真取舍时停下来问**：要放弃他已有的方案、许可证受限（没有许可证 / 不允许复用）、候选互斥（选一个就得放弃另一个，各有明显代价）。
- 没有真取舍：**一句话说出你的决定就继续**——“我看了你已有的和本机市场，`arxiv-digest` 的取 RSS 那段能直接用，我拿来改成中文摘要，其余自己写。”或“没找到合适的，我从头写。”**不要**在两个不冲突的候选之间硬停下问“A+B 还是从头写”。

### 3. 搭骨架，用一篇样例摆出第一版卡片

读 `references/plugin-layout.md`，然后：

```bash
mkdir -p "<工作区根>/plugins/<名字>"
cp -R "<本技能>/assets/plugin-skeleton/." "<工作区根>/plugins/<名字>/"
```

（第 1 步写的 `intent.md` 已在这个文件夹里，骨架不带它，不会被覆盖。）把骨架里的 `__…__` 占位全换掉。**只能写在 `<工作区根>/plugins/<名字>/` 里面。** 这一步**还不要**写技能、脚本，**也不要**去爬真实数据。

要写的三样东西（面板块在 `.claude-plugin/plugin.json` 的 `orbita.panel` 里）：

```json
"panel": {
  "title": "文献追踪",
  "template": "./panel/index.html",
  "data": "${CLAUDE_PLUGIN_ROOT}/data/panel.json",
  "spec": "./panel/spec.md",
  "sample": "./panel/sample.json"
}
```

- **`panel/sample.json`**：**1 篇真文章**（或 3 条左右样例）。数据文件 `data` 还不存在 / 为空时，右栏用它渲染，并标“样例”。**它的形状就是以后脚本要写进 `panel.json` 的形状**（字段名一一对应），所以现在就按你打算让脚本产出的字段来写。取样例的办法：用户给了文章 / 链接就用他的；没有就用一次快速请求取**一条**真的（订阅源的第一条，别翻页别批量）；取不到就自己写 2–3 条像样的，并**明说“这是我编的样例”**。
- **`panel/index.html`**：以 `../panel-style/assets/panel-template.html` 为底，只改渲染部分。**第一版从用户的品味出发**，不要从零造风格：先找品味记录——本工作区 `plugins/*/taste.md`、`plugins/.style-ledger.json`、`intent.md` 的品味参照、你在对话或记忆里已知的他选过的风格（例如“他选过『分诊』”）。有就以它为底做第一版，并告诉他“我从你上次选的 X 出发”；一条都没有，再按 `../panel-style/SKILL.md` 挑**一个**起点（只出一个，不出三个）。写模板必须守 panel-style 里的“八条规则”。
- **`panel/spec.md`**：给人看的短 markdown，只写三件事——**显示哪些字段**（卡上从上到下每一块是什么、对应样例里的哪个字段）、**怎么排**（排序、分组、数量上限）、**数据从哪来**（现在是样例；以后哪个脚本写进 `data/panel.json`）。不写长。

`plugin.json` 这一步**先不写 `orbita.workflow`**（技能还没有；第 5 步技能写好后再补，每步点名真有的技能）。

三样写好后调用：

```
preview_plugin({ path: "<工作区根>/plugins/<名字>" })
```

它**只扫描、不安装**，让右栏出现“正在做”视图：卡片（用样例渲染）+ 下面的 spec。**调一次就够**——之后你改这三个文件，右栏几秒内自己跟着变，**别每改一次调一次**；他说右栏没出现再调。返回里有“要修的东西”就修（工作流点名的技能还没写不算，先不管）。

然后只对他说两三句：右栏现在是什么（这是用他选过的 X 做的第一版，用的是哪一篇）、**问他哪里想改**。**停。** 不要在这一步摆出多个方向，不要问“你还想要什么字段”的长清单。

### 4. 和用户磨卡片（一次改一处）

用户提意见，你改。规矩：

- **一次改一处**：他提哪一处你改哪一处，不顺手“优化”别的。他一句话里提了三处，就改三处，但每一处单独做、单独说。
- **改完告诉他改了哪**：一句话，指到卡上的位置（“问题句挪到第二行了，判定旁边加了『同向 / 对立』”）。然后 **`spec.md` 跟着更新**（改了字段 / 排法就改对应一行；要新字段就同时补 `sample.json`）。
- 你有想法可以说，但**最多问一个问题**，且是对着眼前这张卡问。
- **他对整体风格不满意**（“不是这种感觉”“太像 XX 了”）才换风格：走 `../panel-style/SKILL.md` 的“换风格”，出 2–3 个**骨架不同**的方向（用同一篇样例渲染），他挑一个。局部意见（“字大一点”“这一栏去掉”）就地改，不要因此重新出方向。
- **他说“可以 / 就这样”**才定稿：
  1. 写 `plugins/<名字>/taste.md`：选了什么、否决了什么、他的**原话**（逐字）、日期、适用范围；
  2. `spec.md` 开头标“定稿 v1”；
  3. 说一句“这句我记进插件里的 taste.md 了”，并告诉他你接下来去写脚本、跑真数据，**不再等他确认**。
- 这一步**不写脚本、不爬数据**。

### 5. 定稿之后：写技能和脚本，试跑，批量

按 `references/skill-writing.md` 写每条技能（SKILL.md 的 description 要具体、“推”一点）。技能骨架在 `<本技能>/assets/skill-skeleton/`，脚本放 `scripts/`。写好后补上 `plugin.json` 的 `orbita.workflow`（给人看的步骤，每步点名本插件真有的技能）。

- **脚本的输出形状 = `sample.json` 的形状**。想加字段：先改 `spec.md` 和 `sample.json`（卡片也要跟着改，回第 4 步和他说一声），再改脚本。
- **先试跑几条**（3–5 条）：写到 `orbita.panel.data` 指向的文件（默认 `plugins/<名字>/data/panel.json`）——**右栏会自动从样例换成真数据**，告诉他这一点，并给他看 2–3 条真实记录（不是整个文件）。
- **试跑只是看一眼**：看脚本跑得通、产出的形状对、卡片拿真数据好不好看。**不要把验收清单在试跑里全部做完**，也不要为了“全部打勾”反复改脚本再跑。把做到了什么、没做到什么、没验证什么**如实**告诉他（见下面“做对的标准”）。
- 试跑通过（有产出、形状对）就**直接批量跑**，不用再问。量很大 / 要很久 / 要花钱（逐条调模型）才先说一声。
- 数据必须是真的。网络不通、接口变了就如实说，不要编造当产出；用样例预览要明说是样例。

### 6. 装之前问一句，同意才装

做好后，**先在对话里用一句话问**：“做好了，可以装了吗？（会装进『<工作区名>』，只在这个工作区启用）”**然后停**，不要在同一轮里调用 `install_plugin`。他说可以（或类似的话）才调：

```
install_plugin({ path: "<工作区根>/plugins/<名字>" })
```

它**立即返回**，不等人。两种结果：

- **“Installed”**：已经装上了，对话里自动留了一行“已装上 X · [卸载]”。**别重复那一行的内容**，直接说下一步（右栏会打开插件页并选中它）。技能要到**下一轮**才加载，要试就让他新开一条对话，或你直接按它的 SKILL.md 做一次演示。
- **“Not installed yet”**：它带 MCP（会在本机启动程序）、或范围是所有工作区、或这条会话在 Manual 权限档，所以没装，对话里留了一行带 [安装] 的行。**这一轮到此结束**：用一句话告诉他那一行在等他点（什么时候点都行，之后再开这条会话也还在），**别复述那一行已经写出来的命令和原因、别重调、别催、别在文字里再问一遍**。

返回错误（清单不对、重名、路径越界）时，错误里写了怎么改，改完再调。他说“先别装”“再改改”就回第 4 步。

### 7. 问要不要自动化

最后问一句：“要不要让它每个工作日早上自己跑一次？”**只是提议**：自动化里“选插件”这块还没做，你不会、也不该替他建；把入口技能名和建议的时间告诉他，说清楚现在要定时只能自己在自动化里建一条指向这个技能的任务。

## 做对的标准

- 用户在任何一步说“不是这样”，改，别辩解；他的原话写进 `taste.md` 或 `intent.md`。
- 每次给用户看东西，都是**真路径**；数据要么是真的、要么明说是样例。
- 用他的语言，大白话，不堆术语（“工作流”“技能”可以说，“manifest”“frontmatter”别说）。
- 不在用户的机器上装全局依赖（`pip install`、`npm i -g`），脚本只用标准库；真需要第三方库先问。
- 密钥、令牌不写进任何文件；需要时用 plugin.json 的 `userConfig`（`sensitive: true`），脚本从环境变量读。
- **诚实汇报验证了什么**：做完在对话里给一张**小结**：插件名、放在哪、技能列表、一句话怎么用、**没验证的是什么**（例如“只试跑了 5 条，没跑全量”“没有看卡片在深色主题下的样子”）。看不了图就说看不了图，别写“渲染正常”。

## 常见走偏（遇到先对照这里）

| 现象 | 原因 | 做法 |
|---|---|---|
| 还没和用户定卡片你就在写脚本 / 爬数据 | 把第 5 步提前了 | 停。回第 3 步：样例 + 第一版卡片，先让他看 |
| 一次摆出好几个完整方向 | 把“换风格”当成了第一步 | 第一版只出一个，从他的品味出发；他对整体不满意才出方向 |
| 找完现成的硬停下问“A 还是 B” | 两个候选其实不冲突 | 自己定，一句话说出决定，继续 |
| 右栏没出现“正在做” | 没调 `preview_plugin`，或路径不在工作区里，或清单读不了 | 看工具返回；路径必须在 `<工作区根>/plugins/<名字>/` |
| `install_plugin` 报“outside this session's workspace” | 插件不在工作区里 | 搬到 `<工作区根>/plugins/<名字>/` |
| 报 workflow 点名了不存在的技能 | `skill` 写的既不是技能目录名也不是 SKILL.md 里的 name | 改成本插件里真有的 |
| 装好了但新对话里看不到技能 | 技能下一轮才加载；或 SKILL.md 缺 description | 看返回信息；补 description |
| 面板一直是样例 / 空态 | `panel.json` 路径对不上，或脚本写到了别处 | `orbita.panel.data` 里的路径就是脚本该写的路径 |
| 面板里点链接没反应 | 面板在沙盒里，不能跳转、不能联网 | 链接当文字显示，或发一个 `orbita:action` |
| 与用户已有技能重名 | 技能目录名撞了 | 改插件里的技能名（目录名和 SKILL.md 的 name 一起改） |
