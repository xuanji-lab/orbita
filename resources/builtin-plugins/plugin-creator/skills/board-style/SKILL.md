# 看板卡片：卡里是你的，外框是 Orbita 的

> 改编自 impeccable（Apache-2.0）、花叔 Design（MIT）、Anthropic frontend-design（Apache-2.0），署名见插件根目录 NOTICE。

**语言**：用用户自己写的文字的语言回复（他中文写就中文回），别被消息里英文的系统包装带成英文。

## 什么时候用这个技能

- **做第一张卡 / 新做一张卡（plugin-creator 的看板那步）**：只用到下面「卡片是什么样的」和 `assets/board-template.html`。**第一版从用户已有的品味出发**（`taste.md`、intent 里的品味参照、他这次说的话），只出一个；一条品味记录都找不到时，从这张卡的内容自己推一个起点，并用一句话告诉他为什么。
- **用户对某张卡的整体风格不满意**（「不是这种感觉」「太像 XX 了」）：走下面的「换风格」，出 2 个骨架不同的方向，用**同一份样例数据**渲染，让他挑。**这是子流程，不是开场**：他还没看过这张卡之前，不要摆方向。
- 局部意见（「字大一点」「把作者去掉」「这一栏挪上去」）：**不要用它**，直接在那张卡的模板里改那一处，改完告诉他改了哪。

## 你会滑向哪（已花掉的第一反应）

没有约束时，你会落到下面几处。它们不丑，但与内容无关地出现，读起来就是「AI 做的」或「像某一家」：

- **Kimi 看板那一套**：深蓝渐变大卡 + 浅蓝小卡 + 黑底超大数字。**这套不要做**——那是别人家的看板，一句都别借。
- 分诊式：判定徽章 + 三格信号条、汇总卡大数字 + 分布条。
- SaaS 卡片套件：一样的圆角、一样的浅阴影、`01 / 02 / 03` 编号、全大写小标签、中点串。
- 深底单点缀（近黑底 + 一个荧光色）；平涂色块 + 黑粗描边 + 硬偏移投影；发丝线零圆角报纸风。

这些**不是禁令清单，是「已经花掉的第一反应」**：卡里的颜色、字号、背景、排版本来就是发挥的空间——发挥的方向从这张卡的内容里长出来，不从别家产品抄。

## 卡片是什么样的（先记住）

- **外框是 Orbita 的**：宿主画卡的外框（圆角、裁切）、卡外的标题行（时间 · 插件名）、四档尺寸的格子。**模板里不画外框**：根元素不要 border-radius、边框、卡片阴影，宽高撑满整张卡。卡**里面**的背景色、文字颜色、字号、小色块的圆角，都是你的。
- 四档尺寸：`"1x1" / "2x1" / "1x2" / "2x2"`（宽×高），格子宽高比 10:9。**一张卡只说一件事**（「今日一篇」是一张，「本周汇总」是另一张）；塞不下就减内容或拆卡，不是往小里缩字。
- 一份**自包含的 HTML**：内联 `<style>` / `<script>`，图片字体只能 `data:`，**不能联网、不能引外部文件、不能用 `eval` / `new Function`**。在沙盒 iframe 里，不能跳转链接。
- 浅色 / 玄主题都要成立（宿主下发主题变量，见 `assets/board-template.html`）。
- 宿主 → 模板一条 `orbita:data` 消息：`m.data` 是这张卡的数据文件内容（空态时 `null`、`m.state === "empty"`）；`m.card` 是 `{ id, size, index }`——`repeat` 卡用它知道自己是数组里第几项；`m.unit` 是**一格**的 `{ width, height }` 像素（整张卡 = 格数 × unit + 格间距）——**字号按它等比取**；`m.theme` 的 `vars` 设到 `:root`、`scheme` 是 `"light"` / `"dark"`。数据变化、换主题、换尺寸都会再来一条，**渲染要能重复做**（先清空再画，不要追加）。
- 数据：卡的 `data` 文件不存在 / 为空 → 宿主用 `sample` 渲染并在卡外标「样例」。模板里**不区分**样例和真数据。
- 用样例渲染时宿主会在卡的右上角盖一个约 20px 高的「样例」小标：卡顶那一行（标题 / 日期）右侧留出空位，别让字被盖住。
- 动作按钮发 `orbita:action`（宿主记进 actions.jsonl，会自动带上是哪张卡）。

### 写模板的规矩（实测出来的）

`assets/board-template.html` 已全部做到，**以它为底改渲染部分，别动收发那套**：

1. **自包含**：样式与脚本都内联；图片 / 字体只能 `data:`；不联网、不引外部文件、不用 `eval` / `new Function`。
2. **`<meta name="color-scheme" content="light dark">`**，html 背景透明；卡的背景画在 body 上（这是发挥的地方）。不写 color-scheme，玄主题下会被浏览器刷成不透明白底。
3. **只信宿主的消息**：`if (event.source !== parent) return;`。
4. **样式用宿主变量并带回退**：`var(--color-text-primary, #202124)`、`var(--font-size-sm, 13px)`。变量名单与兜底值见模板；拿不到 Orbita 打包的字体，用系统字体栈兜底。
5. **字号按 unit 等比**：模板把根 font-size 设成 `min(unit.width, unit.height × 10 / 9) / 16` 像素（四档之间也大致等比），CSS 全用 rem。小卡上放不下就减内容，别缩到看不清。
6. **空态**：自己画了空态就发 `parent.postMessage({ type: "orbita:ready", emptyState: true }, "*")`；不发也行，但数据为空时宿主会盖一行「还没有产出」。
7. **动作只是「记一笔」**：`parent.postMessage({ type: "orbita:action", action, payload }, "*")`，动作名 ≤ 64 字符、载荷序列化后 ≤ 16 KB、每 10 秒 ≤ 20 条；宿主只追加进 actions.jsonl，不替你做别的，你的脚本下一轮去读。
8. **大小上限**：数据 / 样例各 ≤ 2 MB、模板 ≤ 1 MB、spec ≤ 64 KB（超了宿主拒读）。
- 正文对比度 ≥ 4.5:1。这是给人每天扫一眼的东西，精确与克制优先于表现力。

## 做一张卡的步骤

1. **先写样例数据**（这张卡的 `sample` 文件）：**1 条真记录最好**。用户给过文章 / 链接就用他的；没有就用一次快速请求取一条（别批量）；取不到就自己编一条像样的，并**明说「这是我编的样例」**。它的形状 = 以后脚本写进这张卡 `data` 文件的形状（字段名一一对应）。参考 `assets/sample.example.json`。
2. **从品味出发定起点**：读本工作区 `plugins/*/taste.md`、intent 里的品味参照、他在对话里说的话。有品味记录就以它为底，告诉他「我从你上次选的 X 出发」；一条都没有，就从这张卡的内容推（这类内容最像什么日常物件、哪个颜色属于它），一句话说清为什么。
3. **写模板**：拷 `assets/board-template.html` 为 `board/<卡id>.html`，只改渲染部分和样式，守上面的规矩。
4. **自己先预览**：拷 `assets/board-preview.html` 为 `board/preview.html`，旁边写 `board/sample-data.js`（`window.__SAMPLE__ = <样例内容>;`）和 `board/drafts.js`（`window.__DRAFTS__ = [{ "name": "…", "file": "<卡id>.html" }];`），用浏览器打开 `?scheme=light` 和 `?scheme=dark` 各看一遍——它把卡放进和宿主一样大的格子里、连外框一起模拟。有明显问题（溢出、对比度、空白）就改，最多两轮。**看不了图就明说**，把路径给用户让他开。
5. **右栏看真格的**：清单里这张卡的 `template` / `sample` 都写了，右栏几秒内自己出现这张卡（`preview_plugin` 调过就不用再调）。问他哪里想改。**停。**

## 换风格（他对某张卡的整体风格不满意时）

1. 只针对那张卡。读它的 sample、`taste.md`、他说的话（「太像 XX 了」「不是这种感觉」）。
2. 出 **2 个方向**（不出三个），必须**骨架不同**（不是换配色）：信息的排列方式、哪个元素最大、条目之间的关系（堆叠 / 列表行 / 表格 / 单个大数字）至少两样不同。都从这张卡的内容推，别落到「已花掉」清单里；每个方向写两行说明（借的是什么规则、签名元素是什么）。
3. 每个方向一份 HTML 放 `board/drafts/`（`a-<名>.html`、`b-<名>.html`），**用同一份 sample** 渲染；preview 页把两个列一起对比。
4. **摆出来就停**，等他挑，不替他选。挑中之后：把挑中的拷成 `board/<卡id>.html`，删掉 `drafts/`、`preview.html`、`sample-data.js`、`drafts.js`（留着会被当成插件内容），`taste.md` 记一笔（选了什么、否决了什么、他的原话逐字、日期、适用范围）。

## 自审（写完模板、给用户看之前问自己）

1. **同类测试**：换一种内容（论文换成天气），我会做出几乎一样的卡吗？会，就是没从内容长出来。
2. **去掉测试**：把最大胆的那一处（签名元素）去掉，信息是更清楚还是更糊？更清楚，说明它用力过头了。
3. **默认测试**：它落在「已花掉」清单里的哪一条上了？像哪家现成产品吗？
4. **一眼测试**：他要在这张卡上做的那个动作（比如扫一眼决定读不读），3 秒内能完成吗？

## 以后再改这张卡

先读 `taste.md` 和现有模板，照它的方向改，不重新激发。用户说「换一个」才走「换风格」。微调（密度、字重、留白）就地改，把非默认的选择写回 `taste.md`。

**诚实汇报你验证过什么。** 看不了图就明说「我看不了图」；只写你真验证过的（文字出来了没有、点击有没有反应、控制台有没有报错），**不要写「渲染正常」「版式没问题」**——版式由用户看。
