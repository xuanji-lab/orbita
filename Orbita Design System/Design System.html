Orbita Design System

Orbita is a desktop agent workbench — an Electron app whose primary surface is a single-agent conversation. The character it aims for is a quiet, editorial workbench with brand-grade craft: not a dashboard, not a cockpit. Opening the app lands directly in Agent mode, where a brand-serif slogan and one input box carry the entire home screen. Multi-agent complexity is deliberately hidden inside the (not yet shipped) orchestration mode.

The interface is built from frosted-glass cards with unified, stacking translucency. The whole app is one large semi-transparent card — the boundary of the application, sidebar included. The content pane floats inside it with an even gap on all four sides, and its left edge is what sets the sidebar's width; the sidebar itself has no surface, sitting directly on the boundary. The input box and session cards float one level higher. Every layer paints the same alpha: the ladder (.60 → .84 → .936) is what compositing produces, not three authored values, so depth cannot drift out of sync. The same card recipe is reused everywhere by changing only width and height.

Information follows one rule: simple by default, expandable on demand. Thinking, tool calls and file reads collapse to a single line until clicked. Restraint is the discipline: no emoji, no piles of colour and counters, every colour with exactly one job.

Content fundamentals

The product ships bilingual (src/i18n/enUS.ts / zhCN.ts). English UI copy is the reference below; brand copy — the slogan — stays in Chinese and is deliberately not run through i18n.

  • Voice: flat, mechanical, unhurried. Labels are nouns or bare verbs: "New Session", "Search", "Start Agent", "Model", "Files", "Confirm". Toasts state what happened, nothing more: "Session opened", "Agent created", "Project refreshed", "Share link copied".
  • Sentence case everywhere. "New workspace name", "Remove workspace", "Main workspace". No Title Case, no ALL CAPS except acronyms. ORBITA appears capitalised only inside prose that names the app ("It may have been removed outside ORBITA."); the wordmark itself is lowercase.
  • Second person, only when the user must act. "You can retry this view or reload the app." Never first person, never "we". The agent does not speak about itself in the UI chrome.
  • Consequences before actions. "Remove this workspace? Its branch and directory will be deleted. This cannot be undone." Destructive copy names the object, the effect, and the finality — in that order, in three short sentences.
  • Refusals explain the blocker, not the rule. "There are running agents in this workspace. Close them before removing." "This project is not a Git repository, cannot enable workspaces."
  • Placeholders invite, they don't instruct. The composer reads "Ask anything, or start a task"; a name field reads "Enter branch or workspace name".
  • Interpolation is plain and terse: "Switched to {name}", "{count} more sessions…", "{days}d ago", "Moved {count} file(s)". Counts stay numeric; units abbreviate (d, s).
  • Ellipsis for in-flight, past tense for done. "Creating...", "Loading…" → "Workspace created: ", "File renamed".
  • Tooltips carry the second half of the sentence. Icons get their meaning from title: "Read-only (tools can only read) · click to make writable", "Archive (planned)", "Opens with the orchestration phase". The centre dot · is the standard connector.
  • Planned features are shown, disabled, and labelled as planned — never hidden, never faked.
  • No emoji. Anywhere. Emoji that previously stood in for group labels were replaced with Lucide glyphs (see atom-group-label). Do not reintroduce them, including in headings and empty states.
  • Mono for machine facts. Paths, ids, branch names, durations, model names and counts are set in the mono/tabular face so a number never re-flows a row.
  • The slogan is the one lyrical line in the product: 璇玑运转，诸事得序 — set in the brand serif at 36px, letter-spaced, centred. Nothing else on the home screen competes with it.

Visual foundations

Colour. Two themes only: white + blue and black + yellow. A warm off-white shell (#f3f4f1) with pure-white panels, three text greys, three hairline greys. Every colour has exactly one job: the accent is blue #1d4ed8 on light and yellow #e3c25a on dark, and it means the single primary action (the send button, "New task", "Start Agent") plus the selected mode — nothing else; amber #b7791f means running; info blue #2563eb marks the thinking glyph; red #b42318 is failure. Status prefers icons and words over colour — a spinner, a check, a lock glyph. List rows never tint: hover and active share one neutral fill and active is marked by weight. Max two background colours per screen. The dark theme is a cool near-black (#111315 shell, #1d2024 panel) with the yellow accent (#e3c25a) on dark glyph colour (--color-accent-fg).

Type. Two families do everything. Brand serif Literata (variable, with Source Han Serif SC for CJK) appears exactly twice: the home slogan and the sidebar wordmark. UI sans Manrope (variable, with Source Han Sans SC) runs the whole interface on a tight 11 → 20px scale, with a separate 15px/1.68 track for transcript prose and a mono/tabular face for machine facts. Weights: 400 body, 500 controls, 600 titles, 650 for tool and card names, 700 for the chat header. Model and thinking-level labels in the composer bar are set italic at secondary grey — the only italic in the UI.

Layout. A fixed shell: left sidebar (288px, collapsing to a 48px icon rail), conversation pane, a 32px action rail for session actions, right drawer (320px, closed by default). Both sidebars are unbounded — no fill, no border, no dividers — so the pane's edges are the only structure. The sidebar lists two nodes: Workspaces (each holding tasks, with its own new-task control) and Tasks for anything belonging to no workspace. One shared measure — --content-max-width: 1000px — governs the transcript, the composer and the home card, which is why the input box keeps the same width from the home screen to the chat page. Density is balanced: 32/36/48px row heights, 24–36px controls, never IDE-crowded.

Backgrounds. No imagery, no illustration, no pattern, no texture, no photography — the product ships none and this system adds none. The only gradient is the desk behind the glass (a soft warm off-white wash) plus two functional gradients in the app (a radial accent glow on the boot screen, and the mark gradient on the legacy logo block). Depth comes from translucency and hairlines, not from colour.

Transparency and blur. Blur is only for surfaces: blur(20px) over a single --glass-bg. One alpha, applied at every level; nesting produces the ladder (1-(1-a)ⁿ), so light reads .60 / .84 / .936 and dark .70 / .91 / .973. The two themes are deliberately unequal — dark blocks more — because light text needs a settled ground and a bleeding wallpaper costs more there. Text is always a solid --color-text-*; never a translucent glyph, and never a dimmed tertiary on glass, which reads as neither theme's ink. Layer 3 is close enough to opaque that content on it reads as if on paper.

Corners and borders. 8px base radius: 4/6/8/10px steps, a literal 14px for the user bubble, and 999px only for true circles (dots, spinners, the round send button). Radius follows the surface, not the element: every glass card takes --radius-xl (10px) whatever its layer, so the composer — a glass card — is 10px, not 14px. Borders are always 1px hairlines; glass cards border with rgba(255,255,255,.55), though the app shell and content pane run borderless and rely on the translucency step alone. No thick rules, no coloured left-border accents.

Cards. One recipe: the single --glass-bg, 1px light border, --shadow-composer (0 8px 28px rgba(20,24,31,.08)), 10px radius. Chat-internal cards (tool, thinking) have no border and no fill — they sit directly on the chat surface and are separated by 16px of space. Solid panels (dialogs, drawers) are white with a hairline and a heavier shadow.

Shadows. Four steps, all cool-grey and soft: --shadow-border (a 1px inner hairline), --shadow-composer (cards and the input box), --shadow-popover (menus, card hover), --shadow-modal (dialogs). Focus is a 2px accent ring at 16% opacity, plus a solid accent outline on :focus-visible.

Hover, press, disabled. Hover fills with the next grey up (--color-bg-hover) and lifts text from secondary to primary — never a colour change, never a transform. Cards lift their shadow from composer to popover, and nothing moves. Press deepens the fill (--color-bg-active); accent buttons go to --color-accent-strong (#16379c). Disabled is opacity: .45–.55 with cursor: not-allowed — and for planned features, a title explaining why. On glass, disable with a solid theme colour rather than opacity: a dimmed glyph over translucency reads as neither ink nor wallpaper.

Motion. Motion only ever explains where things went. 120ms for hover and row state, 140ms for the composer's border and shadow, 160ms for chevrons, 220ms for the slogan and session cards fading up and out, 240ms for the composer gliding to the bottom of the window and becoming the chat composer. Easing is cubic-bezier(.22,1,.36,1) for entrances and cubic-bezier(.4,0,.6,1) for that one travel. There is no idle animation, no bounce, no parallax; prefers-reduced-motion collapses everything to 0.01ms.

Iconography

  • Lucide, and only Lucide. The app uses lucide-react at runtime; design/icons/lucide/ holds the matching static set (2,034 SVGs, lucide-static@1.33.0, ISC licence). The 46 glyphs this system uses are copied into assets/icons/lucide/ — no CDN, no substitution, no hand-drawn SVG.
  • Sizes: 16px in the rail, headers and dialogs; 13–14px in chips, list rows and card headers; 11–12px for inline affordances (locks, filters, counts). Stroke weight 1.8 in lists and trees, 2 for controls, 2.2 for the modal close.
  • Icons inherit currentColor — tertiary grey at rest, primary on hover, --color-info for the thinking glyph, the accent inside the send button. The Icon component inlines the SVG so this works.
  • Recurring vocabulary: bot = agent mode, workflow = orchestration, folder = a workspace, plus = new task, folder-plus = new workspace, gauge = usage, archive = archived tasks, git-branch = a worktree, and the task-row status slot — loader-circle running, check finished, triangle-alert failed, empty when idle, lock/lock-open = read-only, brain = thinking, terminal/wrench/file-text = tool calls, hat-glasses = anonymous chat, panel-left/panel-right = the two sidebars, arrow-up = send.
  • No emoji, no Unicode glyphs as icons, no icon font, no PNG icons. The only raster assets in the source are third-party editor logos (VS Code, Cursor, Zed, JetBrains) used in the editor picker; they are not part of the brand and are not copied here.

Intentional additions

  • Icon — a thin wrapper that inlines the copied Lucide SVGs so they inherit currentColor. The app gets this from lucide-react, which is not available here; the wrapper is the closest equivalent, not a new design decision.
  • AssistantText and Chip are extracted from CSS classes in the source (.assistant-text, .home-chip / .composer .input-chip) that had no standalone component.

Nothing else was invented: there is no Toast, Tabs, Avatar, Tooltip or Switch here because the source does not define them.

Caveats

  • docs/orbita-design.md — the written design-language spec — was not mounted. Values here come from the code; the spec may be more current on intent.
  • The webfonts are shipped not yet wired into the app: renderer/src/styles.css still runs a system font stack and still declares an older commercial-substitute set (PlantinNowVariable, CommitMono, DepartureMono) left over from a previous theme. This system follows design/README.md, which supersedes those with Literata + Manrope + Source Han.
  • No monospace brand face was specified, so the mono token falls back to the system mono stack (ui-monospace, SFMono-Regular, Menlo, …). If Orbita picks a mono, it belongs in tokens/fonts.css.
  • The renderer contains large unshipped or legacy areas — orchestration (atom), Feishu, the browser panel, the terminal dock, the desktop pet, the Monaco editor and the config tabs. They are named here but not recreated, because their current visuals are explicitly in flux.
