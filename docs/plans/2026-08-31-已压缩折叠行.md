# 刀 0-3 · 压缩不再混进对话——「已压缩」折叠行

> 批次 0 执行清单的第三刀。**视图规则是 pi 的语义**：压缩之后，压缩前的往来对视图
> 隐藏，只留一条折叠界碑，点开是摘要全文；原始记录仍全量在我们自己的 JSONL 里。

## 调研结论（方案的地基，全部核对到行号）

**pi 侧（核对安装的 0.84.3 dist，非 pi-main 参考）**：

- 压缩对外只经 `compaction_start` / `compaction_end` 事件暴露
  （`pi-coding-agent/dist/core/agent-session.d.ts`）；`compaction_end.result:
  CompactionResult`，字段 `summary / firstKeptEntryId / tokensBefore`。
  **摘要不在任何 TranscriptItem 里**——pi-protocol 的 transcript 只有 user / assistant / tool。
- pi 自己的 JSONL append-only，压缩 = 追加一条 compaction entry；重载时
  `buildContextEntries` 只保留**最后一条压缩边界**之后的往来。
- pi TUI 的显示（平面移植对象）：`CompactionSummaryMessageComponent`——
  折叠 `[compaction] Compacted from N tokens`，展开是摘要 markdown。

**本地侧（改前）**：

- `runtime.ts` 的 `ADAPTABLE_TYPES` 把 compaction 事件全丢 → 压缩**静默发生**：
  UI 无任何变化，我们的 JSONL 照旧全量落盘，重开显示全部历史（与 pi 本子的
  上下文不一致）。
- `store.readLog` 裸 `JSON.parse` + cast，无 schema 校验 → 新记录类型对旧文件零兼容成本。
- renderer 槽的 transcript 走 pi 自带归约器 → **界碑不能混进归约器**（它不认识），
  槽里并列 `compactions` 数组，显示时合成。

## 核心判断：偏离执行清单的「visibility 包装」

执行清单建议「落盘时包一层 `{ item, visibility: user | internal | delegated }`」。
调研后改用**专用记录类型** `CompactedRecord { role: "compacted", … }`：

- 今天唯一的内部记录就是压缩边界，一个专用 role 就是它的 visibility；
  通用三枚举没有第二个消费者。
- 等委派（delegated）真开工时协议加字段是加法，不需要提前占位（AGENTS.md）。
- 读写两端都少一层解包，旧日志零迁移。

## 数据流（改后）

```
pi compaction_start ──→ runtime 发 phase "compaction"（UI 忙碌；renderer 现有映射自动处理）
pi compaction_end ───→ runtime 发 phase "idle"
                        aborted / 无 result → 不发界碑（历史没被折叠）
                        其余 → 发 { type: "compaction", record }
recorder ────────────→ 界碑落一行 JSON（与消息共用日志，append-only）
readLog ─────────────→ isCompactedRecord 逐字段校验分流；冒充界碑的坏行跳过
seedFromDisk ────────→ 界碑进槽的 compactions，往来进 pi 归约器（实时与历史同一条显示路径）
applyCompactionBoundary → 界碑按时间插回往来流；无界碑原样；有界碑只显最后一条
                         边界之后（同毫秒界碑在前）——pi buildContextEntries 同款语义
ChatView ────────────→ CompactedLine：archive 图标 +「已压缩 · 此前上下文约 N tokens」
                         + chevron，默认折叠；展开 = MarkdownBlock(摘要)，320px 封顶
```

## 这一刀不做什么

- 不加通用 `visibility` 字段（理由见上）。
- 不做手动 `/compact` 或「压缩上下文」按钮——pi 的 `session.compact()` 已具备，
  等真实消费者另立小刀（它同时也是比「长会话自然触发」更好的验收工具）。
- 不读 pi 的 session 文件做边界推导——边界自己落一行，唯一真源是我们自己的 JSONL。
- 不做「显示被压缩的原始消息」——原始记录仍全量在盘上，视图按 pi 语义隐藏；
  界碑行不提供绕过。
- transcriptToMarkdown 的 `role: "tool"` 缺口维持刀 0-2「另行成刀」的决定。

## 测试

- shared：`isCompactedRecord` 正常 / 缺字段 / role 冒充；导出界碑出标记行 + 引用块摘要。
- recorder：compaction 事件原样落盘；界碑不挤占标题推导。
- store：混合日志回读分流；坏界碑行跳过；旧格式日志原样。
- session-states：事件进槽不进归约器；seedFromDisk 分流；
  `applyCompactionBoundary` 无界碑 / 单边界 / 多边界 / 同毫秒。

## 已知边界

- 时间戳归并依赖同机时钟（本地优先应用，成立）。
- 导出 Markdown 与「复制整条对话」：界碑出标记 + 摘要；导出的是**全量**历史
  （含压缩前的往来），与视图的边界规则是两回事——导出给人存档，视图给人读。
