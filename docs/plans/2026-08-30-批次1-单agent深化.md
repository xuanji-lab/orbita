## A 组 · 让长会话可用（3 刀）

长会话现在有三个盲区：不知道离爆上下文还有多远、压缩时以为卡死了、重试时以为没反应。

### A-1 · 看得到上下文余量、token 与花费

**演示**：跑十几轮对话，输入卡底栏显示 `18.2k / 200k · $0.06`；hover 看到 input/output/缓存分项。

**pi 已提供**：`session.getSessionStats()` 返回
```text
{ tokens: { input, output, cacheRead, cacheWrite, total }, cost,
  contextUsage?, toolCalls, toolResults, userMessages, assistantMessages }
```

**改哪里**
- `src/shared/agent-ipc.ts` — 加一个 stats 通道（**协议改动单独成 PR**）
- `src/agent/runtime.ts` — 每轮结束时读 `getSessionStats()` 并推给主进程
- `src/main/agent/ipc.ts` + `src/preload/api/agent.ts` — 四层贯通
- `ChatView.tsx` 的 `ComposerBar` — 显示

**判断点**：推送时机。每个 token 都推会刷爆 IPC。建议 `agent_settled` 时推一次 +
压缩前后各推一次。定了写进 PR 描述。

**不要顺手做**：不要做用量历史曲线；不要做预算告警；不要把 stats 落盘（那是以后的事）。

---

### A-2 · 压缩时界面说「正在压缩」而不是干等

**演示**：跑一条长到触发自动压缩的会话，压缩那几秒界面显示「正在压缩上下文」而不是 `Responding`。

**pi 已提供**：`compaction_start` / `compaction_end` 事件，都带 `reason: "manual" | "threshold" | "overflow"`；
`compaction_end` 还有 `result` / `aborted` / `willRetry`。**就在 `AgentSessionEvent` 里，`session.subscribe()` 直接拿得到。**

**改哪里**
- `src/shared/agent-ipc.ts` — `phase` 现在只有 `idle | turn`，协议里本来是五档
  （`idle | turn | compaction | branch_summary | retry`）。补齐（**协议 PR**）
- `src/agent/runtime.ts` — 订阅两个事件，发 phase
- `useChatSession.ts` — `phase` 类型现在写死了 `"idle" | "turn"`
- `ChatView.tsx` — `Responding` 组件按 phase 变文案

**不要顺手做**：不要做手动压缩按钮（那是另一刀）；不要显示压缩省了多少 token。

---

### A-3 · 重试时看得到第几次、还等多久

**演示**：断网发一句，界面显示「连接失败，第 2 次重试，3 秒后」，而不是一直转圈。

**pi 已提供**：`auto_retry_start`（`attempt` / `maxAttempts` / `delayMs` / `errorMessage`）、
`auto_retry_end`（`success` / `attempt`）。

**改哪里**：同 A-2 的四层，phase 用 `retry`，另需把 attempt/delayMs 带给 renderer。

**不要顺手做**：不要做「立即重试」按钮；不要改 pi 的重试策略（那要碰 `RetrySettings`，是另一件事）。

## B 组 · 读得舒服（3 刀）

### B-1 · 代码块高亮 ⚠️ 唯一需要新依赖的一刀

**演示**：agent 回答里的代码块有语法高亮，明暗主题各自正确。

**pi 提供了什么**：`highlightCode` / `getMarkdownTheme` / `Theme`——**但那是给 TUI 的**
（`modes/interactive/theme/theme.ts`），输出的是终端色码，不能直接用在 DOM 上。

**所以这一刀要先调研**：按仓库规矩「先调研再新增依赖，明确版本与维护状态」。
候选是 shiki（Proma 在用，`packages/core/src/highlight/shiki-service.ts` 275 行可参考）。

**要一起想清楚的**：性能。Proma 的教训是流式渲染时每帧重新高亮会卡——
它们的 release note 记着「单 Agent 运行 20 分钟后输入按键延迟 38ms→185ms」。
**高亮结果要按语言 + 内容缓存，流式中的代码块不要每帧重算。**

**不要顺手做**：不要顺手上 Mermaid；不要做代码块复制按钮。

---

### B-2 · Edit 工具显示内联 diff

**演示**：让 agent 改一个文件，那条工具行展开后是带增删标记的 diff，不是一坨文本。

**pi 已提供，而且已经算好了**：`EditToolDetails { diff, patch, firstChangedLine }`。
**`details` 已经在 transcript 里了**（`c5f1604e` 补的），直接读 `item.details.diff`。

**改哪里**
- `src/renderer/src/features/chat/tool-results.ts` — 加一个「这条结果有没有 diff」的判定（纯函数）
- `ChatView.tsx` 的 `ToolLine` — 展开区按工具类型分支：edit 走 diff 渲染，其余走原文

**不要顺手做**：不要给别的工具也做定制渲染（grep 高亮、read 行号都是后面的）；
不要做 diff 的折叠/展开上下文行数控制。

## C 组 · 会话能力（4 刀）

### C-1 · 运行中打的字排队可见

**演示**：agent 正在回答时打一句话回车，它显示为「排队中」，当前轮结束后自动发出。

**pi 已提供**：`queue_update` 事件，带 `steering: readonly string[]` 与 `followUp: readonly string[]`。

**要先弄清楚的**：pi 区分 steering（插话，影响当前轮）与 followUp（下一轮）。
`session.steeringMode` / `followUpMode` 各有 `"all" | "one-at-a-time"` 两档。
**这一刀先只做「看得见」，不做「选哪种」。**

**不要顺手做**：不要做排队项的删除/重排；不要暴露 steeringMode 开关。

### C-2 · 会话可从某条消息另起一支 ⚠️ 有语义依赖

**演示**：在某条历史消息上点「从这里分支」，开出一条新会话，前文保留、后文不带。

**pi 已提供**：`SessionManager.branch(id)` / `branchWithSummary()` /
`createBranchedSession(leafId)` / `forkFrom()` / `getTree(): SessionTreeNode[]` /
`getBranch(fromId)` / `getChildren(parentId)`。**整套都是现成的。**

**语义依赖**：需要 `SessionMeta` 对未知字段向前兼容（肖志锋的 0-4）。
**没等到就自己先加**——那是 20 行加一个测试，撞了合并时留一份。

**不要顺手做**：不要做会话树的可视化（那是大件）；先做「能分支」，不做「能看到分支结构」。

### C-3 · 会话标题由模型生成

**演示**：发完第一句，侧栏标题从「首句截断」变成模型概括的短标题。

**现状**：`shared/session.ts` 的 `deriveSessionTitle` 取首句，`:19` 标注了这是临时方案。

**判断点**：用哪个模型、什么时候触发、失败了怎么办。建议：当前会话同一个模型、
第一轮结束后异步触发、失败就保留首句截断（**不要让标题生成失败影响对话**）。

**可参考**：旧分支有一份 `auto-titler.ts`（`git show wip/home-view-zcode:<path>`），
guideline §八 把它列为「后续单独捞」的三样之一。

**不要顺手做**：不要做手动重新生成标题的入口。

## 与批次 0 合并后怎么验没坏

每次和肖志锋的分支合并后：

```bash
bun run typecheck        # 退出 0
bun run test             # 全绿（当前基线 167）
bun run dev              # 起来后手动跑一遍下面三条
```

手动三条（覆盖两边都动过的地方）：

1. **发一句话，让 agent 执行 `ls src`** —— 工具行能展开（0-1 的功能没被碰坏）
2. **跑到触发压缩** —— 内部消息不出现在对话里（0-3），同时 phase 显示压缩（A-2）
3. **切一次会话再切回来** —— 消息不串台

**合并冲突集中在 `useChatSession.ts` 的 `onEvent`**：两边都在往那串 `if` 里加分支。
手工合并时把两边的分支都留下，然后跑上面三条。

## 纪律（同批次 0）

1. **一刀 = 一个可演示的行为变化 + 测试 + 真实调用点。**
