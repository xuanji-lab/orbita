# 用户输入的数学公式渲染（2026-09-05）

> 第一站验证黑色皮肤时由用户提出的缺口：theme-black-X 的 KaTeX 渲染只覆盖**模型输出**
> （MarkdownBlock），用户自己打的公式在气泡里是一坨源码。本刀把渲染接给用户输入。

## 范围（用户裁决，2026-09-05）

1. **核心：用户气泡公式渲染。** 发送后，用户消息里的 `$…$` 行内公式就地渲染（跟着文字流走）、
   `$$…$$` 块级公式单独一行居中；**其余文字与 markdown 记号原样**——用户气泡不渲染 markdown。
2. **附加：Σ 按钮门控的按需预览。** 草稿含 `$` 时，发送键左侧浮出 sigma（Σ）次级按钮；
   点击在 textarea 与底栏之间展开预览条，随打字实时更新；再点收起；`$` 删光则按钮与
   预览条一起消失。**草稿无 `$` 时输入卡与今天一个像素不差。**

## 设计决定与被否决项

- **输入框常驻预览条——否决**（用户否决：输入卡会长成一张大卡片，为小众场景永久膨胀）。
- **输入框内所见即所得——否决**（要换编辑器组件，光标 / 中文输入法组词都是坑，工程量数倍）。
- **气泡整套 markdown——否决**（用户只点名公式；全渲染会让粘贴文本里的 `*` `_` `#` 被重排）。
- **「发送即预览」成立**：打字时看到的是 LaTeX 源码本身，发送后气泡里立刻看到渲染结果，
  不对就改了重发——不需要输入框内的实时渲染兜底，Σ 按钮只是发送前想先检查的人的选项。

## 与模型输出渲染同一套语义（复用，不另起炉灶）

- **金额防误判**：行内公式的值贴空白（`$5 and $10`）不是公式，保持纯文本——`math-guard.ts`
  同一条规则，用户输入与模型输出行为一致。
- **流式补全**：结尾悬着的未闭合 `$` 按已闭合渲染——`pending-math.ts` 同一条规则。
- **安全闸**：KaTeX `trust: false`、`throwOnError: false`，与 MarkdownBlock 相同配置；
  katex.min.css 已随 MarkdownBlock 模块全局加载，气泡侧零新增加载。

## 实现

- 新增 `math-text.ts`：纯函数 `splitMathSegments(text)`，把文本切成
  `text / inlineMath / blockMath` 三种段（上述两条规则内建）。node --test 可测，附
  `math-text.test.ts`（正常路径 + 金额 + 未闭合 + 无公式快路径 + `$$` 内嵌 `$` 边界）。
- `UserBubble` 的 text 块从纯 `<span>` 换成解析器渲染（KaTeX `dangerouslySetInnerHTML`，
  输出受 trust:false 约束）。
- `Composer` 加门控 Σ 按钮 + 可折叠预览条（渲染同一解析器）；补 `sigma.svg` 进设计系统
  lucide 资产并注册进 `Icon.tsx`（fold-vertical 同模式）。
- 功能分支：基于 `merge/turn-rollup-X`，独立一刀，验收后与集成一起推送。
