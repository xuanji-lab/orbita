# 用户输入的数学公式渲染（2026-09-05）

> 第一站验证黑色皮肤时由用户提出的缺口：theme-black-X 的 KaTeX 渲染只覆盖**模型输出**
> （MarkdownBlock），用户自己打的公式在气泡里是一坨源码。本刀把渲染接给用户输入。

## 范围（用户裁决，2026-09-05，两次收窄后定稿）

**只做一件事：用户气泡公式渲染。** 发送后，用户消息里的 `$…$` 行内公式就地渲染
（跟着文字流走）、`$$…$$` 块级公式单独一行居中；**其余文字与 markdown 记号原样**——
用户气泡不渲染 markdown。「发送即预览」：打字时看到 LaTeX 源码本身，发送后气泡里
立刻看到成形效果，不对就改了重发。**输入框完全不动。**

## 设计决定与被否决项

- **输入框常驻预览条——否决**（用户否决：输入卡会长成一张大卡片，为小众场景永久膨胀）。
- **输入框内所见即所得——否决**（要换编辑器组件，光标 / 中文输入法组词都是坑，工程量数倍）。
- **气泡整套 markdown——否决**（用户只点名公式；全渲染会让粘贴文本里的 `*` `_` `#` 被重排）。
- **Σ 按钮门控的按需预览——已实现后被否决删除**（2026-09-05）：草稿含 `$` 时浮现 Σ
  按钮、点开展开 UserBubble 同款预览卡。实现小样后用户裁决「卡片太丑」——输入框
  一寸都不该动，删除该功能（sigma.svg 与 Composer 改动一并回退）。「发送即预览」
  已覆盖检查公式的需求，预览卡是多余的第三处渲染面。

## 与模型输出渲染同一套语义（复用，不另起炉灶）

- **金额防误判**：行内公式的值贴空白（`$5 and $10`）不是公式，保持纯文本——`math-guard.ts`
  同一条规则，用户输入与模型输出行为一致。
- **流式补全**：结尾悬着的未闭合 `$` 按已闭合渲染——`pending-math.ts` 同一条规则。
- **安全闸**：KaTeX `trust: false`、`throwOnError: false`，与 MarkdownBlock 相同配置；
  katex.min.css 已随 MarkdownBlock 模块全局加载，气泡侧零新增加载。

## 实现

- `shell/math-text.ts`：纯函数 `splitMathSegments(text)`，把文本切成
  `text / inlineMath / blockMath` 三种段（上述两条规则内建），附 `math-text.test.ts`
  （正常路径 + 金额 + 未闭合 + 无公式快路径 + `$$` 内嵌 `$` 边界 + 往返无损不变量）。
- `shell/MathText.tsx`：切分结果的渲染组件（KaTeX dangerouslySetInnerHTML，
  输出受 trust:false 约束；块级 display:block 居中）。
- `ChatView` 的 `UserBubble`：text 块从纯 `<span>` 换成 MathText。
- 功能分支：基于 `merge/turn-rollup-X`（`user-math-X`），独立一刀，验收后与集成一起推送。
