# 2026-08-31 · 会话切换实时刷新

> 症状：会话 A 在跑，切去看 B 再切回来——只更新一小段就卡住，每切一次才动一次。
> 根因不在 recorder、不在 pi，在 renderer 的状态形状。

## 根因（已核实到行）

事件链路本身是通的：runtime 给每个 session 的事件都带 `sessionId`
（`src/agent/runtime.ts:166`），主进程原样广播给所有窗口（`src/main/agent/ipc.ts:100`）。
丢事件的地方全在 `useChatSession.ts`：

1. **全 hook 只有一份 `TranscriptState`**（`:89`），事件回调里
   `event.sessionId !== sessionRef.current` 就丢弃（`:154`）——后台会话的事件不是
   「攒着」，是直接扔掉。
2. `openSession()` 切回任何会话都走**磁盘加载**并把 `sessionId` 置 `null`（`:248`）。
   切回还在跑的 A：读到的是 recorder 已落盘的终态帧（所以是「一部分」），
   然后 `sessionRef.current === null`，A 的活事件继续被丢——卡住。
   每切一次 = 读一次盘 = 更新一点。

同一条路径上的两个连带雷：

- **后台审批挂死**：A 在后台弹审批，被同一行过滤器丢弃，而 runtime 的
  `askPermission` 没有超时（`runtime.ts:60`）——A 永远等不到答复，切回来也看不到审批条。
- **resume 双开**：从磁盘看着 A 时发消息，`send()` 走 resume→create，
  runtime 的 `sessions.set()`（`runtime.ts:174`）**不退订不 dispose 直接覆盖**还活着的
  A——泄漏 + 两个 AgentSession 写同一份 pi JSONL（记录写坏级事故）。

## 方案（六问已定，全取推荐）

1. **renderer 按会话分槽**：`Map<sessionId, Entry>`，Entry = `{ transcript, phase, approvals }`。
   progress / phase / permission 事件**无条件**写进自己会话的槽——不再有「看谁才记谁」。
   切会话只是换显示哪一槽。零新增 IPC：事件本来就全到了 renderer，只是被扔了。
2. **live 集合本地记**：`useRef(new Set<string>())`，send 创建成功时加入，
   runtime 崩溃（`failed` 且 `sessionId === null`）时清空。`openSession` 命中 live 集合
   → 重连（`sessionId = id`，**不用磁盘快照覆盖槽**）；未命中 → 照旧磁盘加载种槽。
3. **审批按会话分槽**：后台弹的审批进 A 的槽，切回 A 就能看到、能应答。
   `requestId` 是 `${sessionId}:${toolCallId}`，全局唯一，按它跨槽摘除。
4. **runtime 双开守卫**：`createSession` 开头同 id 已活即拒绝（约两行）。
   UI 修好后正常操作到不了这条路径，它是 JSONL 写坏的保险丝。
5. **归约逻辑抽成纯模块单测**：renderer 没装 @testing-library，现有 renderer 测试全是
   纯函数测试——纯模块按现有方式测，顺带把债务 B 点名的「sessionId 过滤串台」回归网补上。
6. **独立 `fix(chat)` PR**；工作区里刀 0-2 的 `recorder.test.ts` 改动不动，那条刀继续。

### hook 返回形状不变

ChatView / Sidebar 只消费 `ChatSession` 的现有字段。接线方式：states Map 进 React state，
「当前看哪条」**不新增状态**——沿用 `sessionId ?? opened?.id`（ChatView 本来就这么推），
派生出当前槽。`phase / approvals / transcript` 从当前槽读。渲染组件零改动。

## 被否决的方案

| 方案 | 为什么不要 |
|---|---|
| 主进程存快照、切换时拉（新增四层契约 IPC） | 能扛 renderer 重载，但「重载丢状态」是今天的现状不是本次回归；shared 契约单独成 PR，成本远超收益。等真被咬再上。 |
| 只做「切回时重放/拉取」，不做后台累积 | 切换瞬间仍要一次拉取，且后台事件照旧丢失、后台审批照旧挂死。分槽天然把两件事一起解决。 |
| Map 写在 hook 里不抽纯模块 | 现有测试基建测不了 hook，串台回归网落不了地（Q5 定案）。 |

## 这一刀不做什么（写进 PR 描述）

- 不做主进程快照、不做「列出活会话」IPC（Q1/Q2 否决项）
- 不做会话销毁 / disposeSession——那是刀 0-4 债务 A
- 不动 JSONL 格式、不动 recorder——那是刀 0-2
- **已知的顶**：renderer 重载后 live 集合丢失，此时对还在跑的会话发消息会被 runtime
  守卫拒绝并如实报错，不做自动恢复。dev 场景（HMR）才容易触发，撞到再议。

## 测试

纯模块用例（`bun run test` 现有基建直接跑）：

1. A/B 事件交错 → 各槽独立增长，互不含对方内容（**串台回归网**，债务 B）
2. A 持续涨与「当前看谁」无关——后台累积的等价断言
3. permission 进对应槽；`removeApproval` 按 requestId 跨槽摘除
4. phase 按槽独立（A turn 与 B idle 并存）；`markAllIdle` 清全部
5. `seedFromDisk` 覆盖旧槽（重开历史会话拿到磁盘真相）

runtime 守卫是两行平凡分支，不单测（runtime.ts 是 utility 进程脚本，无导出，不为其建测试壳）。

## 验收（手动演示）

1. A 跑长任务 → 切到 B 看历史 → 切回 A：**不读盘、不卡**，直接是最新且持续实时涨。
2. A 后台弹审批 → 切回 A 看到审批条，应答后工具继续跑。
3. 杀掉 agent 进程（模拟崩溃）→ 回到磁盘加载行为，界面如实显示错误。
