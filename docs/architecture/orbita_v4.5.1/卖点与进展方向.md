## 卖点（璇玑 独特价值）

1. **通用底座，领域中立** — 核心微内核零领域语义字段（无 filePath/repoUrl/cwd）。coding 是 Pack 不是核心，任何领域可插拔；核心空核但开箱即用（默认依赖 coding-pack）。见原则 18、18-domain-pack.md。

2. **四库对称，含 Loop 库** — 身份/提示词/技能/Loop 四库对称，各自多层加载（pack<builtin<user<project<group）。Loop 库（执行引擎可插拔）为 璇玑 独有，其他多 Agent 框架硬编码单一 Loop。见原则 19、04-four-libraries.md。

3. **两层 Pattern 可组装** — Coordination（怎么组织 agent：hierarchy/market/...）× Execution（怎么执行任务：dag/tournament/chain/fan-out）独立可组合，Capability 契约保证组合合法。不锁定单一编排方式。见原则 20、03-execution-modes.md。

4. **任事型三模式 + 谋士型 council** — 朝廷（hierarchy 文官体制）/竞功（market 军事体制）/大明（混编+效率转模）+ 谋士型（council 协调拓扑）。任事型三模式共享术语池，谋士型独立。见原则 30/33、12~17 各模式文档。

5. **司礼监编排协调中枢** — 不只是前置关口（代批），而是全程参与的协调中枢。七项职责：前置过滤/意图探索/有限代批/模式推荐/编排初始化/全程协调/结果汇总。让 PatternRuntime（皇帝）保持全程低上下文最高效决策状态。司礼监是参谋+管家，不做决策（决策权在皇帝）。见 15-sijian-batch.md §1a、02-architecture-layers.md §3。

6. **军功簿学习闭环** — WeightRegistry 跨任务记录 Identity/Agent 表现，按权重推荐/选择，表现稳定升权、不佳降权，ε-greedy 防过早收敛。越用越聪明。见原则 23、07-infrastructure.md。Phase 2（2026-07）：FileWeightRegistry 持久化激活 + Tournament adjustedScore 公式接入，闭环已验证（cross-session 记忆 + 跨任务权重学习）。

7. **图状通信** — 点对点 + 发布订阅 + 频道三种通信模式。市场 Coordination 下竞争者间禁止横向通信（公平性不变量）；跨用户通信需 Trust Level 授权。见原则 13、01-overview §8.3。

8. **事件溯源状态** — 所有状态变更是 append-only 事件，状态是事件投影。天然支持审计、回放、并发；命名空间分权，Agent 只看有权分区。见 01-overview §8.4、06-core-engine.md。

9. **三层监察 + 权力分离** — 过程监督（仅暂停）/事后审计（建议性或权重影响）/高风险复核（强制推翻）三层；暂停权与恢复权分离；监察者改写/暂停记录进事件流，可被更高层采样复审。见原则 24、01-overview §8.5。

10. **User 一等公民** — UserProfile（identity/permissions/quotas/memory）。多用户协作是一等场景：跨用户复用专家、多用户 Tournament vote、协作 Session 责任追溯。Phase 3 完整落地。见原则 25、01-overview §8.7。

11. **双宪法体系** — 架构宪法（代码强制，core-invariants 硬编码）+ 身份宪法（专家判断）。解决"修改规则的人不能同时是被规则约束的人"的自引用问题。见原则 10、01-overview §9。

12. **渐进自主性** — 框架提供通用编排模式 → Agent 自由组装 → 用户自己组装。自由度递增，璇玑 的演进方向是渐进放权。见 AGENTS.md §0、README v3→v4 变化。

13. **AgentGroup 六部编组** — Agent 持久化编组（Session 级），有内部层级（尚书/侍郎）、专属频道、跨部协同（会推/会审/专行/管班）、元监察（东厂/锦衣卫）。源于明朝六部体系，经历史验证。AgentGroup 是 Composition 层概念（非微内核一等概念）。见 11-renshi-shared-base.md §23。

## 进展方向（未来演进）

1. **通用化深入**（P0） — coding-pack 是第一个官方 Pack。目标是从单一 coding 扩展到多领域 Pack 生态（research/writing/数据分析/...）。核心保持空核，领域能力全部通过 Domain Pack 注入。见原则 18、18-domain-pack.md。

2. **自主性递增**（P0） — 框架提供通用编排模式 → Agent 在 Composition Layer 自由组装 Pattern → 用户用 Preset 自己组装。璇玑 演进方向是渐进放权（AGENTS.md §0）。Phase 3.3 完成 TuiApp 渲染集成，用户侧自主性进一步提升。见原则 29、01-overview §8.8。

3. **协作规模扩展**（P1） — 少量 Agent → 海量 Agent（dispatchBudget 预算驱动，不按数量限制，架构硬兜底 10）；单用户 → 多用户实时协作（Phase 3 完成：协作 Session、跨用户专家复用、Tournament 真人 vote、Trust Level 授权）。Phase 3.3 闭环，测试覆盖 cell-base 749 + orbita-cli 1072。见原则 4/25。

4. **模式生态扩展**（P1） — 当前任事型三模式（朝廷/竞功/大明）+ 谋士型 council。Phase 2+ 引入 peer-mesh（同辈网状）、federation（联邦）等新 Coordination Pattern，可插拔注册。T7 自检确认 6 一等概念 + 7 一等层稳定，无新增/降级。见原则 20、01-overview §6。

5. **学习与记忆增强**（P2） — Phase 1 WeightRegistry 为 NoOp → Phase 2 持久化（SQLite）+ 军功簿影响权重 → 跨 session 记忆（UserProfile.memory）→ 自优化。从每次从零到越用越懂用户。Phase 3.3 无新增，Phase 4 重点。见原则 23/25。

6. **Phase 分阶段落地**（P2） — Phase 1 给最笨实现（接口已是终局形态）→ Phase 2 持久化与扩展 → Phase 3 多用户实时 → Phase 3.3 闭环（TuiApp + 透明性 UI + dispatch_subagent + 1072 tests）。核心逻辑跨阶段零改动（原则 2）。终局目标：多人在线 + 海量 agent + 复杂拓扑。

7. **接缝持续兑现 + 断链回写**（P1） — 七维度插件化（角色/拓扑/通信/状态/监察/生命周期/能力发现/Loop/User）逐步从 Phase 1 最笨实现升级到终局实现。每个维度升级 = 换实现不改接口。**Phase 3.3 闭环后重点**：T8 反向断链回写（Surface/EntryEvent/DualSurfaceLayout/αβ 模式设计决策补录）。见 01-overview §10、05-agent-roles.md。
