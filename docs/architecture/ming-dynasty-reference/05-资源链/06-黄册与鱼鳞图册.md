## 黄册——户籍册

### 什么是黄册

黄册是明代的**全国户口登记册**，每十年重编一次。内容包括每家每户的人口（姓名、年龄、性别、与户主的关系）、财产（田地、房屋、牲畜）、赋税（应纳税粮数）。

**为什么叫"黄册"**：呈送户部的正本用黄纸做封面（黄色在古代是中央官方的颜色）。

**编制层级**：
```
户（家庭）→ 里（110户）→ 县 → 府 → 布政司 → 户部
```

每级都要抄录副本——全国汇总的黄册堆积在南京后湖（玄武湖）的黄册库中。

### 黄册的内容

每户登记的基本信息（以洪武格式为例）：

| 字段 | 内容 | 用途 |
|:--|:--|:--|
| 户主姓名 | 户主+所有家庭成员的名字和年龄 | 确定丁口数（赋税和徭役的基础） |
| 户籍类别 | 民户/军户/匠户/灶户（盐户）——世袭不可改变 | 决定应承担的赋役类型——军户出壮丁、匠户服工匠役、灶户煮盐 |
| 财产登记 | 田地多少亩（"旧管"=上次登记数、"新收"=新增数、"开除"=减少数、"实在"=现在实际数） | 田赋的计算基础 |
| 赋税 | 该户应纳税粮石数 | 征税的依据 |
| 人丁变动 | 上次登记后出生/死亡/嫁娶的人口变化 | 更新丁口数据 |

### "四柱清册"格式

黄册用的是中国传统的"四柱"记账法，也是世界上最早的复式记账体系之一：

| 柱 | 含义 | 示例 |
|:--|:--|:--|
| **旧管** | 上次编制的数据（baseline） | "洪武十四年册：田五十亩" |
| **新收** | 这十年间新增的 | "新买田五亩" |
| **开除** | 这十年间减少的 | "被洪水冲毁田三亩" |
| **实在** | 现在的实际数据 | "实在：田五十二亩" |

这种格式使每次重编都能追溯到变化——从制度上为审计留下了线索。

### 黄册的衰败

黄册制度在明中期后逐渐失效：
- **地方官敷衍**：每十年重编一次工作量巨大，地方官越来越倾向于照抄上次的数据微调——数据的更新频率从十年变成三十年、五十年
- **豪强隐匿田产**：大地主买通胥吏（衙门底层办事员），将自己的田产"挂"到穷人户上或干脆不登记——黄册上的"实在"数据和实际情况越来越脱节
- **胥吏的灰色权力**：编制黄册的巨大工作量使基层胥吏掌握了大量自由裁量权——谁能少报田产取决于谁给了胥吏好处
- **数据不可靠的连锁反应**：黄册不准确 → 赋税分配不公 → 贫户承担了（实际上不存在的）田产的赋税 → 贫户逃亡 → 黄册数据更失真

## 鱼鳞图册——土地册

### 什么是鱼鳞图册

鱼鳞图册是明代的**土地登记图册**——把每一块耕地的形状画在纸上并标注面积和所有者。因为图上的地块像鱼鳞一样密集排列，所以称为"鱼鳞图册"。

**与黄册的区别**：

| | 黄册 | 鱼鳞图册 |
|:--|:--|:--|
| 以什么为核心 | **户**（家庭）——每家有多少人、多少地 | **地**（地块）——每块地在哪、多大、谁的 |
| 主要回答 | "这家人该交多少税" | "这块地被谁占了、该不该交税" |
| 更新频率 | 十年 | 不定（理论上随田地变更而更新，实际很少更新） |

两者是同一个赋税体系的两面——黄册负责"向谁收"、鱼鳞图册负责"该不该收"。

### 编制过程

洪武初年，朱元璋派人到全国范围丈量土地——这是中国古代史上最大规模的土地调查之一。每个县的土地被逐块编号、丈量、绘图、登记所有者。

鱼鳞图册的精度在明初非常高——据说朱元璋通过鱼鳞图册可以知道全国每一块耕地的大小和所有者。

### 鱼鳞图册的衰败

类似黄册——明中后期土地兼并严重、豪强隐匿田产、鱼鳞图册多年不更新，到万历年间已经严重失真。张居正推行一条鞭法前在全国重新丈量土地（万历清丈），试图恢复鱼鳞图册的准确性——这是明朝最后一次大规模的数据校正尝试。张居正死后清丈停止，土地数据再次快速退化。

---

## 数据崩溃的连锁反应

黄册和鱼鳞图册的共同衰败产生了从基层到中央的崩塌链：

```
土地数据失真 → 赋税分配不公 → 贫户负担过重 → 逃亡弃田
    → 税基缩小（因为田地被抛荒 + 豪强隐匿不报）
    → 朝廷税收减少 → 加税 → 更多贫户逃亡
    → 财政崩溃
```

**核心教训**：赋税制度的公正性依赖于**数据基础设施的可信性**。当黄册和鱼鳞图册不再可信，整个赋税体系就建立在谎言之上——而谎言堆积得越久，修正的代价就越大。明末朝廷不是不知道数据失真——而是已经没有能力再做一次全国性的土地清丈了。

## 编排参考

- "黄册的四柱清册格式" → **编排系统的状态快照机制**：档籍 Agent 在每次状态变更时记录（旧管/新收/开除/实在）——类似 Git 的 version diff。这不仅能追溯发生了什么，还能追溯"为什么变化"（哪个操作导致了变化）
- "黄册十年一造" → **定期快照 vs 实时更新的权衡**：全量同步（十年重编）成本高但数据结构一致；增量更新（只记变化）成本低但可能累积误差。编排系统需要两种模式并存——定期全量快照 + 增量日志
- "豪强隐匿田产" → **特权 Agent 绕过资源计量的风险**：如果某些 Agent 可以"隐匿"自己的资源消耗（像豪强隐匿田产），太仓库的出纳日报就会失真——需要像万历清丈那样的周期性全量审计
- "胥吏的自由裁量权" → **基层执行层的灰色空间**：胥吏（基层办事员）在编制黄册时有巨大的自由裁量权——编排系统的科员级 Agent 在执行底层操作时也有类似的灰色空间。监督需要嵌入操作流程而非事后抽查
- "黄册+鱼鳞图册的双重验证" → **以户为中心和以资源为中心的双重视图**：一个视图看"谁消耗了什么"（以 Agent 为单位 = 黄册），一个视图看"什么被谁消耗了"（以资源为单位 = 鱼鳞图册）。两个视图互相验证——任何不一致都触发审计
